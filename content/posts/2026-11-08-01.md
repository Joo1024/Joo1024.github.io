在进一步开发 Flowfolio 之前，我想先弄清楚四个问题。

1. 机构如何制定、检验、执行和调整量化策略？回测在其中有多重要，其他方法又各能回答什么？这关系到 Flowfolio 会怎么用，以及它需要对外提供哪些能力。
2. 哪些研究方向和信息来源值得长期追踪？
3. Flowfolio 的核心设计在策略研究中处于哪一环？
4. 和现有的量化回测工具相比，Flowfolio 的定位是什么？

## 机构如何研究量化策略

一个常见的做法是先提出可检验的投资假设，把它写成信号和仓位规则，再看它在不同样本、风险约束和交易成本下是否成立。

上线前，历史回测是估计一套规则的收益和风险的重要方法之一。判断一套策略是否值得投入真实资金、能否扩大规模，还要结合样本外检验、成本和容量估计，以及实盘反馈。各类证据的权重取决于策略。月度资产配置依赖足够长、覆盖多种市场环境的历史，做市则尤其依赖真实的排队、成交和延迟数据。公开资料能看到一些共通做法，具体准入门槛和内部流程因机构而异。

### 制定策略

机构研究通常从一个可检验的目标出发。主动选股关心某种信息能否预测相对收益，趋势跟踪关心价格变化能否延续，再平衡关心怎样以更低的成本让仓位保持在目标附近。想法可以来自经济机制、交易制度、组合管理需求或数据探索。通过数据探索得到的候选规则，需要用未参与选择的数据检验。 [AQR 系统化股票投资](https://www.aqr.com/Learning-Center/Systematic-Equities) · [Two Sigma 投资流程](https://www.twosigma.com/businesses/investment-management/)

| 层次 | 要决定的事 |
| --- | --- |
| 信号或触发规则 | 用什么信息，信息何时可见，多久更新一次。例如根据已公布的财报给股票打分，或在观察到配置偏离后触发再平衡。 |
| 组合构建 | 怎样把信号转成目标仓位，如何限制集中度、风险暴露和换手，新策略能给已有组合带来什么。 |
| 执行 | 怎样把目标仓位变成订单，何时下单、如何拆单，以及怎样处理流动性不足或成交不全。 |

这三层可以分别研究。对同一组价值和动量信号，分别构建组合再合并，与先合成打分再构建组合，得到的持仓可能不同。低频配置的重点可能在仓位规则，高频策略的收益则可能直接取决于执行方式。

### 检验策略

回测用当时可获得的信息和给定的交易规则，重建账户可能走过的轨迹。结果是否可信，首先取决于数据时点和执行假设。财报要按实际可获得的时间使用，股票池要反映当时的成分并纳入后来退市的标的，成交要考虑信号和下单的先后。收益要和合适的基准比较，成本则要考虑费用、价差、滑点和市场冲击，以及适用时的融资和借券成本。 [CFA Institute 回测与模拟](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/backtesting-and-simulation) · [CFA Institute 投资模型验证指南](https://rpc.cfainstitute.org/research/foundation/2024/investment-model-validation)

| 方法 | 能回答的问题 |
| --- | --- |
| 信号检验、对照与归因 | 信号能否预测目标变量？关闭某条规则后，组合表现怎样变化？收益优势来自目标信号，还是股票仓位、行业或其他已知因子暴露？ |
| 样本外与跨市场复现 | 用较早数据开发的规则，在未参与选择的较晚区间或其他市场是否仍然有效？需要定期重估时，可以逐期向前滚动，每次只用当时已有的数据。 |
| 统计检验与参数敏感性 | 收益差异有多不确定？相近参数能否得到相近结论？结果是否由少数交易或某一个时期主导？尝试过大量候选时，要把选择过程纳入评估。反复看过并据此改过策略的测试集，应当视为开发数据。 |
| 历史压力测试与假设情景 | 在危机、高通胀或流动性枯竭时，策略会怎样表现？也可以人为提高交易成本、延迟成交，或模拟历史上少见的组合冲击。结论取决于所设定的情景。 |
| 影子运行与模拟盘 | 用实时数据生成目标仓位或模拟订单，检查数据能否按时到达、生产信号是否和研究信号一致，以及系统能否准时运行。模拟成交的可信度取决于成交模型。 |
| 小规模实盘 | 用真实订单观察成交率、拒单、滑点、冲击和实际持仓，检验当前规模下的可执行性。评估长期收益需要积累足够多的独立决策和市场环境，扩大规模时也要重新估计成本。 |

AQR 曾用此前未研究过的 82 个标的复验趋势跟踪，检验规律能否迁移。它的另一项研究用 1.7 万亿美元的历史实盘成交数据估计交易成本和价格冲击。多重检验研究则提醒我，从许多配置里选出的最高 Sharpe 要谨慎解读。 [AQR 跨市场趋势研究](https://www.aqr.com/Insights/Research/Journal-Article/Trends-Everywhere) · [AQR 交易成本研究](https://www.aqr.com/Insights/Research/Working-Paper/Trading-Costs) · [回测过拟合论文](https://escholarship.org/uc/item/4w1110bb)

### 执行策略

上线前，还要确认生产系统能否正确执行已经通过研究的规则。测试包括数据断流、重复订单、部分成交、拒单、持仓对账和异常停机。实盘中，策略生成目标仓位，系统根据实际持仓生成订单，经过交易前风控检查后发往交易场所，再用真实成交更新账户。英国 FCA 的多机构检查记录了分阶段部署和小额实盘试单的做法，美国 FINRA 的指引也提到了限规模试运行、实时监控和快速停用。 [FCA 算法交易多机构检查](https://www.fca.org.uk/publications/multi-firm-reviews/algorithmic-trading-controls-high-level-observations) · [FINRA 算法交易监督指引](https://www.finra.org/rules-guidance/notices/15-09)

资金规模增加时，订单更可能消耗盘口流动性，并影响成交价格。可以把真实成交与决策时的参考价格、模拟成交和预估成本对照，找出差异，再调整下单方式、仓位上限和容量估计。对做市和高频策略，验证还要考虑订单簿排队、部分成交、延迟和成交后的价格变化。 [Man AHL 市场微观结构模拟](https://www.man.com/insights/simulating-financial-markets)

### 调整策略

实盘表现偏离预期时，先判断偏差出在哪一层。回撤可能来自正常波动、市场环境变化、交易成本上升，也可能来自数据或系统故障。 [Man Group 系统化策略的持续评估](https://www.man.com/insights/conviction-the-systematic-hunt) · [Optiver 生产监控与反馈](https://www.optiver.com/what-we-do/research/)

| 观察到的变化 | 对应的检查和动作 |
| --- | --- |
| 组合亏损，信号和成交表现仍在预期范围内 | 做收益与风险归因，检查亏损是否来自已知风险暴露，并按既定风险预算处理。 |
| 信号仍有预测力，但净收益下降 | 对比真实滑点、换手和预估成本，检查是否需要改执行方式、降低换手或缩小规模。 |
| 数据分布、市场制度或信号预测力持续变化 | 回到原假设，检查策略在哪些市场和时段失效。并行评估候选版本，再决定是否替换、降权或退役。 |
| 订单、持仓或数据异常 | 按预设限额和停机流程处理，修复后重测，再受控恢复。 |

按预定规则每月重新估计参数，是策略的一部分。根据近期亏损改动信号、阈值或交易规则，则产生了一个新版本。近期数据可以用来诊断，也已经参与了新版的形成。新版需要独立验证，重大的执行变更还需要重新进行上线测试。

比如，我想比较多个回撤阈值时，可以先在开发样本中比较并记录试过的参数，选定规则后，再到未参与选择的历史区间检验。除了期末账户值和回撤，我也会看股票仓位和现金占比，帮助判断表现差异有多少来自风险暴露的不同。反复在同一段历史上选参数，容易高估表现最好的那套规则。

## 值得长期追踪的方向和来源

我想研究的是目标配置和账户管理。股债比、股票内部的地域和风格配置，决定了账户长期承担哪些风险。持续入金怎么投、要不要留现金等回撤、什么时候再平衡，则决定账户怎样建立和维持这些配置。

Vanguard 的资产配置研究与我的问题最接近。我想把它作为长期追踪的主线，再用 Dimensional 对照同一问题的不同做法，把 CFA Institute 的验证指南留作方法参考。读一篇研究时，我想记下它用了什么基准、哪些假设决定了结果，以及什么情况下结论会变。比如，Vanguard 把再平衡拆成「何时触发」和「调回哪里」，再比较费用与配置偏离。具体阈值是否适合持续入金的账户，需要在相应场景中重新检验。 [Vanguard 投资策略团队](https://corporate.vanguard.com/content/corporatesite/us/en/corp/what-we-think/investing-insights/investment-strategy-group.html) · [Vanguard 研究资料库](https://corporate.vanguard.com/content/corporatesite/us/en/corp/what-we-think/investing-insights/research-library.html) · [Vanguard 战略资产配置](https://corporate.vanguard.com/content/corporatesite/us/en/corp/strategic-asset-allocation.html)

### 账户管理

| 研究问题 | 可以怎么比较 | 参考来源 |
| --- | --- | --- |
| 现金流驱动的再平衡 | 看用新增资金先补低配资产能减少多少卖出、节省多少费用，以及入金相对账户规模变小时，何时仍需要主动调仓。 | [Vanguard 阈值再平衡研究](https://corporate.vanguard.com/content/dam/corp/research/pdf/the_rebalancing_edge_optimizing_target_date_fund_rebalancing_through_threshold_based_strategies.pdf) · [Vanguard 多资产再平衡研究](https://corporate.vanguard.com/content/dam/corp/research/pdf/rational_rebalancing_analytical_approach_to_multiasset_portfolio_rebalancing.pdf) · [Vanguard 目标日期基金的配置与执行](https://workplace.vanguard.com/insights-and-research/perspective/delivering-on-design-disciplined-implementation-in-index-based-target-date-funds.html) · [Dimensional 再平衡的取舍](https://www.dimensional.com/lu-en/insights/finding-your-balance-tradeoffs-and-decisions-in-portfolio-rebalancing) |

我想先做两组比较。第一组固定入金和再平衡规则，只换目标配置，可以从固定股债比、比较全球市值加权和本国超配做起。第二组固定目标配置，只换入金分配和再平衡规则。之后再看两组变量如何相互影响。比如，用新入金补低配资产能否控制配置偏离，会随股债比、市场路径和入金占账户的比例而变化。

## Flowfolio 在策略研究中的位置

**Flowfolio 负责一次回测怎么跑。** 给定策略、场景和执行规则，生成可复现的账户轨迹。场景格式、事件顺序、成交规则和结果格式都属于这一层。这样，研究者可以有意识地只改一个条件，追溯结果是怎样产生的，并从 `RunResult` 计算单次回测的收益、回撤和费用。

**单独的研究仓库负责为什么跑这几次，以及怎样解读结果。** 要检验什么假设、选哪些场景和基准、怎样划分样本、哪些结果放在一起比较，都由具体研究决定。

## Flowfolio 与现有回测工具

Man AHL 公开描述过如何使用内部行情库、可复用的策略组件和统一的模拟流程比较信号。公开文章可以用来参考流程，具体执行假设、成本模型和代码则服务于他们自己的交易环境。 [Man AHL 研究流程](https://www.man.com/insights/ai-agents-trend)

Testfolio 和 Portfolio Visualizer 可以固定历史区间，比较股债比、定期入金和再平衡规则。我把这两种在线工具作为功能参考，也可以用它们做对照验证。 [Testfolio 回测方法](https://testfol.io/guides/portfolio-backtester/) · [Portfolio Visualizer 资产配置回测](https://www.portfoliovisualizer.com/backtest-portfolio)

在 Python 开源工具里，`bt` 和 Backtrader 都在我的考察范围内。`bt` 能把入金、目标权重和再平衡组合成策略，也能把同一策略放到不同数据上跑。策略与场景分开的设计，在现有工具里已经有类似做法。 [bt API 文档](https://pmorissette.github.io/bt/docs/source/overview.html)

如果要把现有开源引擎接入 Flowfolio，作为可替换的执行器，就需要统一输入和输出。输入要约定行情格式、复权方式、入金和成交时点，输出要约定逐笔成交、费用、估值和收益口径。适配时，在这套协议与各个引擎的格式之间做转换。

多引擎兼容有两个用途。其一，同一场景可以交给不同引擎交叉验证，增加对结果的信心。其二，出现差异时，可以分别比较不同引擎在同一场景下的结果，以及直接调用某个引擎和经由 Flowfolio 调用它的结果，帮助定位问题出在适配转换还是引擎本身。

## 开发前准备与首版验证

开发前，我可以先为第一项投资研究选定对照组，明确数据口径和评价指标。我也会准备一个可手算的小场景，写清入金、成交和估值的先后顺序，逐步记下预期的现金余额和持仓。

等首版能完整跑通一次回测，我会用手算结果逐步核对账户轨迹。接入第二个执行器后，再用同一场景检查两个实现是否遵守同一套规则，并看出现的差异能否追溯到具体事件。

投资规则在真实历史样本中的表现，则由独立的研究仓库通过对照实验来评估。
